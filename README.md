# homelab_setup2

Self-hosted homelab on a local k3d cluster: Authentik SSO, GitLab, MinIO,
n8n, SonarQube, Seafile, ArgoCD, an LGTM observability stack, OpenWebUI,
LiteLLM, Nx Cloud, and a set of MCP servers for in-cluster coding agents.
Every app gets SSO via Authentik and is reachable remotely over Tailscale.

Two deployment paths exist side by side:

- **Tilt** — fast local iteration, dev-fixed secrets, auto-reload on file change.
- **Terraform (OpenTofu)** — the "real" deploy, reads the same `.env` values,
  no auto-reload, meant to be run deliberately.

Both read secrets from the same root `.env` file so they never drift apart.

## Prerequisites

- Docker Desktop (or another Docker engine)
- [k3d](https://k3d.io/)
- [Tilt](https://tilt.dev/) (dev path)
- [OpenTofu](https://opentofu.org/) (`tofu`) (prod path) — Terraform CLI works too
- [Tailscale](https://tailscale.com/) client, for remote access to `*.ts.net` URLs
- `kubectl`, `helm`

## Onboarding

```bash
git clone <this repo>
cd homelab_setup2
cp .env.example .env
```

Edit `.env`:
- Set `TS_HOST` to your machine's Tailscale hostname (`tailscale status` or
  the admin console — looks like `your-machine.tail60240b.ts.net`).
- Fill in the values marked `REAL` — see [Access tokens](#access-tokens) below.
- Everything else already has a working dev-placeholder default.

```bash
./scripts/create-cluster.sh   # one-time: creates the k3d cluster
```

### Development (Tilt)

```bash
./scripts/dev-up.sh
```

This sources `.env` and runs `tilt up`. Opens the Tilt web UI; every app in
`helm/*/Tiltfile` deploys with dev-fixed secrets and hot-reloads on change.
Don't run bare `tilt up` — it won't read `.env` and secrets silently fall
back to placeholders (GitHub login breaks first, silently).

`Tiltfile` (repo root) pins `k8s_context('k3d-internal-dev')` — if your
cluster has a different name (`create-cluster.sh` defaults to `internal`,
override with `K3D_CLUSTER_NAME`), update that line or export
`K3D_CLUSTER_NAME=internal-dev` before creating the cluster.

### Production (Terraform)

```bash
./scripts/gen-tfvars.sh              # regenerate terraform/local.auto.tfvars from .env
cd terraform
tofu init                            # first time only
tofu plan
tofu apply
```

`terraform/local.auto.tfvars` is generated, gitignored, and auto-loaded by
Terraform — never edit it by hand, edit `.env` and re-run `gen-tfvars.sh`.

Each `terraform/*.tf` file mirrors its `helm/*/Tiltfile` counterpart 1:1
(same env vars, same OIDC wiring) — if you add an app to one, add it to the
other too, they're expected to stay in sync.

Two provisioners deploy config that outlives a single `helm_release`:
- `null_resource.authentik_app_providers` — creates every app's OAuth2/SAML
  provider inside Authentik (nothing else does this; skipping it means
  every app's "Log in with Authentik" button 404s on a nonexistent client).
- `null_resource.authentik_github_source` — wires GitHub as a login source
  for Authentik's own admin panel, plus auto-promotes `admin_email` to
  Authentik Admins on first GitHub login.

Both re-run automatically (via `triggers`) whenever their relevant secrets
or the underlying Python script change.

## Access tokens

Everything in `.env.example` has a working dev default **except** the
values below — those are real credentials from an external service and
must be generated by hand. Nothing works correctly (SSO, MCP tool auth,
etc.) until these are filled in.

| Variable | Where to get it | What breaks without it |
|---|---|---|
| `TF_VAR_github_oauth_client_id` / `_secret` | [GitHub Developer Settings → OAuth Apps](https://github.com/settings/developers) — callback URL is Authentik's own GitHub source callback, check Authentik → Directory → Federation & Social login → GitHub for the exact URL once Authentik is up | Authentik's own admin login via GitHub |
| `TF_VAR_grafana_mcp_token` | Grafana → Administration → Service accounts → Add service account token | Grafana MCP server — boots fine, every tool call 401s |
| `TF_VAR_sonarqube_mcp_token` | SonarQube → My Account → Security → Generate Token | SonarQube MCP server — boots fine, every tool call 401s |
| `TF_VAR_gitlab_mcp_token` | GitLab → Edit profile → Access Tokens (scope: `api`) | GitLab MCP server — **hard-refuses to start** without this one |
| `TF_VAR_nx_cloud_mcp_token` | Nx Cloud → workspace settings → access token | Optional — Nx MCP server boots and serves Nx Cloud tools without it, some may be limited |
| `TF_VAR_nx_cloud_saml_cert` | Authentik's signing cert PEM (printed by `provision-app-providers.py` between `NX_CLOUD_SAML_CERT_START`/`END` markers after first apply) | Nx Cloud SAML SSO — stays disabled (password-only login) until set |

`TF_VAR_gitlab_mcp_auth_token` is **not** an external credential — it's a
bearer token this repo invents so only intentional clients can call the
GitLab MCP server over HTTP. The dev default works fine everywhere.

`playwright`'s MCP server needs no token at all — it's local browser
automation (its own headless Chromium), nothing external to authenticate
against.

Every other OIDC `client_id`/`client_secret` pair (gitlab, minio, n8n,
sonarqube, seafile, argocd, grafana, openwebui, litellm) is a value **this
repo invents and Authentik trusts** — the dev placeholder is exactly as
real as a generated one, no external step needed. Change them only if you
want non-guessable values for a genuinely internet-exposed deployment.

## Accessing apps

```bash
./scripts/list-urls.sh                        # print every app's URL + live status
./scripts/port-forward-terraform-apps.sh       # start local port-forwards for all terraform-managed apps
./scripts/tailscale-serve.sh                   # map each app's tailnet HTTPS port to its local port-forward
```

Every app is reachable two ways: `https://<TS_HOST>:<port>` from any device
on your tailnet (see `scripts/tailscale-serve.sh` for the port map), or
`https://<app>.local` locally (needs a `/etc/hosts` entry — or Windows
`C:\Windows\System32\drivers\etc\hosts` — plus trusting the homelab's
self-signed CA, `terraform/cert-manager.tf`'s `homelab-ca-issuer`).

`mcp-servers` has no ingress or tailscale port — it's ClusterIP-only,
meant to be called from *inside* the cluster (a coding agent pod), not
browsed to.

## Repo layout

```
helm/<app>/          Helm chart + Tiltfile for each app (dev path)
terraform/<app>.tf   Matching Terraform resource for each app (prod path)
scripts/             Cluster bootstrap, dev wrapper, URL/port-forward helpers
.env / .env.example  Single source of truth for both Tilt and Terraform
```

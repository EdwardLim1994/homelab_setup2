# homelab_setup2

Self-hosted homelab on a local k3d cluster: Authentik SSO, GitLab, MinIO,
n8n, SonarQube, Seafile, ArgoCD, an LGTM observability stack, OpenWebUI,
LiteLLM, Nx Cloud, and a set of MCP servers for in-cluster coding agents.
Every app gets SSO via Authentik and is reachable remotely over Tailscale.

Two deployment paths exist side by side:

- **Tilt** — fast local iteration, dev-fixed secrets, auto-reload on file change.
- **Terraform (OpenTofu)** — the "real" deploy, reads the same `.env` values,
  no auto-reload, meant to be run deliberately.

Both read secrets from the same root `.env` file so they never drift apart.

## Prerequisites

- Docker Desktop (or another Docker engine)
- [k3d](https://k3d.io/)
- [Tilt](https://tilt.dev/) (dev path)
- [OpenTofu](https://opentofu.org/) (`tofu`) (prod path) — Terraform CLI works too
- [Tailscale](https://tailscale.com/) client, for remote access to `*.ts.net` URLs
- `kubectl`, `helm`

## Onboarding

```bash
git clone <this repo>
cd homelab_setup2
cp .env.example .env
```

Edit `.env`:
- Set `TS_HOST` **and** `TF_VAR_ts_host` to your machine's Tailscale hostname
  (`tailscale status`, or the admin console — looks like
  `your-machine.tail60240b.ts.net`). Same value in both, no quotes.
- Fill in the credentials that must be generated by hand — see
  [Environment variables](#environment-variables) below.
- Everything else already has a working dev-placeholder default.

```bash
./scripts/create-cluster.sh   # one-time: creates the k3d cluster
```

### Development (Tilt)

```bash
./scripts/dev-up.sh
```

This sources `.env` and runs `tilt up`. Opens the Tilt web UI; every app in
`helm/*/Tiltfile` deploys with dev-fixed secrets and hot-reloads on change.
Bare `tilt up` also works — the root `Tiltfile` loads `.env` itself — but
real shell env vars still take precedence over `.env`.

`Tiltfile` (repo root) pins `k8s_context('k3d-internal-dev')` — if your
cluster has a different name (`create-cluster.sh` defaults to `internal`,
override with `K3D_CLUSTER_NAME`), update that line or export
`K3D_CLUSTER_NAME=internal-dev` before creating the cluster.

### Production (Terraform)

```bash
./scripts/gen-tfvars.sh              # regenerate terraform/local.auto.tfvars from .env
cd terraform
tofu init                            # first time only
tofu plan
tofu apply
```

`terraform/local.auto.tfvars` is generated, gitignored, and auto-loaded by
Terraform — never edit it by hand, edit `.env` and re-run `gen-tfvars.sh`.

Each `terraform/*.tf` file mirrors its `helm/*/Tiltfile` counterpart 1:1
(same env vars, same OIDC wiring) — if you add an app to one, add it to the
other too, they're expected to stay in sync.

Two provisioners deploy config that outlives a single `helm_release`:
- `null_resource.authentik_app_providers` — creates every app's OAuth2/SAML
  provider inside Authentik (nothing else does this; skipping it means
  every app's "Log in with Authentik" button 404s on a nonexistent client).
- `null_resource.authentik_github_source` — wires GitHub as a login source
  for Authentik's own admin panel, plus auto-promotes `admin_email` to
  Authentik Admins on first GitHub login.

Both re-run automatically (via `triggers`) whenever their relevant secrets
or the underlying Python script change.

## Environment variables

`.env` has three kinds of value. Only the third kind needs real work.

### 1. Dev-fixed — leave them alone

Passwords, DB passwords, encryption/salt keys, and every OIDC
`client_id` / `client_secret` pair (gitlab, minio, n8n, sonarqube, seafile,
argocd, grafana, openwebui, litellm). Authentik trusts whatever value it's
given, so a placeholder is exactly as real as a generated one. The whole
cluster comes up with the shipped defaults untouched.

Only bother changing these for a genuinely internet-exposed deployment. If
you do, generate them and keep the format:

```bash
openssl rand -hex 32                 # generic secret / password / encryption key
printf 'sk-%s\n' "$(openssl rand -hex 24)"   # litellm master / salt key (keep the sk- prefix)
```

Set the new value for the **same variable in `.env`** and redeploy — do not
edit anything under `terraform/` or a running Secret directly.

### 2. `TS_HOST` — your machine

`TS_HOST` and `TF_VAR_ts_host` both = your Tailscale hostname
(`tailscale status`). Nothing SSO- or ingress-related resolves without it.

### 3. Must be generated from an external service

Nothing invents these for you. Some can only be made **after** the relevant
app is up, so the flow is: deploy once → generate → put in `.env` → redeploy.

| Variable | How to generate | Needs app running first? | What breaks without it |
|---|---|---|---|
| `TF_VAR_github_oauth_client_id`<br>`TF_VAR_github_oauth_client_secret` | [github.com/settings/developers](https://github.com/settings/developers) → **New OAuth App**. Homepage: `https://<TS_HOST>:8443`. Authorization callback URL: `https://<TS_HOST>:8443/source/oauth/callback/github/` (confirm the exact path in Authentik → Directory → Federation & Social login → GitHub once it's up). Copy the client ID; **Generate a new client secret** and copy that. | No | Authentik admin login via GitHub |
| `TF_VAR_claude_code_token` | On your own machine with Claude Code installed and logged in (Pro/Max): `claude setup-token` → opens a browser → paste the `sk-ant-oat01-…` line it prints. Long-lived (~1 yr), revocable at [claude.ai](https://claude.ai) → Settings. | No | opencode pods can't auth `claude` (they still start; opencode-via-Ollama still works) |
| `TF_VAR_n8n_api_key` | n8n UI → **Settings → API Keys → Create**. Must be created while logged in as the SSO account you normally use, or seeded workflows show "without permissions". | **Yes** — n8n | SDLC flows (`helm/n8n/flows/F-*.json`) aren't auto-seeded / re-seeded |
| `TF_VAR_grafana_mcp_token` | Grafana → Administration → Users and access → **Service accounts** → add account (role: Editor/Admin) → **Add service account token** → copy. | **Yes** — Grafana | Grafana MCP server boots, every tool call 401s |
| `TF_VAR_sonarqube_mcp_token` | SonarQube → **My Account → Security → Generate Token** (type: User Token) → copy (shown once). | **Yes** — SonarQube | SonarQube MCP server boots, every tool call 401s |
| `TF_VAR_gitlab_mcp_token` | GitLab → **Edit profile → Access Tokens** → new token, scope `api`, expiry as you like → copy. | **Yes** — GitLab | GitLab MCP server **hard-refuses to start** |
| `TF_VAR_nx_cloud_mcp_token` | Nx Cloud → workspace settings → **access token**. Optional. | **Yes** — Nx Cloud | Nx MCP server still boots; some Nx Cloud tools limited |
| `TF_VAR_nx_cloud_saml_cert` | After the first `tofu apply` / `tilt up`, `provision-app-providers.py` prints Authentik's signing cert between `NX_CLOUD_SAML_CERT_START` / `_END` markers — copy the base64 body (one line, no PEM headers). | **Yes** — Authentik | Nx Cloud SAML SSO stays off (password login only) |

### Not real credentials (safe defaults, listed for completeness)

- `TF_VAR_gitlab_mcp_auth_token` — a bearer token **this repo invents** so
  only intended clients reach the GitLab MCP server over HTTP. Default is fine.
- Playwright's MCP server takes no token — it's a local headless Chromium,
  nothing external to authenticate against.

### After editing `.env` for a Terraform deploy

```bash
./scripts/gen-tfvars.sh            # regenerate terraform/local.auto.tfvars
cd terraform && tofu apply
```

For Tilt, re-run `./scripts/dev-up.sh` (or just save any watched file — the
Tiltfiles read `.env` on load).

## Accessing apps

```bash
./scripts/list-urls.sh                        # print every app's URL + live status
./scripts/port-forward-terraform-apps.sh       # start local port-forwards for all terraform-managed apps
./scripts/tailscale-serve.sh                   # map each app's tailnet HTTPS port to its local port-forward
```

Every app is reachable two ways: `https://<TS_HOST>:<port>` from any device
on your tailnet (see `scripts/tailscale-serve.sh` for the port map), or
`https://<app>.local` locally (needs a `/etc/hosts` entry — or Windows
`C:\Windows\System32\drivers\etc\hosts` — plus trusting the homelab's
self-signed CA, `terraform/cert-manager.tf`'s `homelab-ca-issuer`).

`mcp-servers` has no ingress or tailscale port — it's ClusterIP-only,
meant to be called from *inside* the cluster (a coding agent pod), not
browsed to.

## Repo layout

```
helm/<app>/          Helm chart + Tiltfile for each app (dev path)
terraform/<app>.tf   Matching Terraform resource for each app (prod path)
scripts/             Cluster bootstrap, dev wrapper, URL/port-forward helpers
.env / .env.example  Single source of truth for both Tilt and Terraform
```
